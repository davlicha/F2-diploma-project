| --- | --- |
| Статус | Approved |

## Context

Agent Orchestrator виконує сеанс планування як послідовність із чотирьох агентів з умовним
циклом Reviewer → Planner. SRS накладає такі обмеження на механізм оркестрування:

1. Стан сеансу повинен зберігатися після кожного кроку та відновлюватися після перезапуску
   процесу з втратою не більше одного кроку (SRS-FUN-12, SRS-NFR-REL-03).
2. Цикл верифікації повинен бути обмежений кількістю ітерацій (SRS-FUN-10).
3. Виконання повинно призупинятися до рішення користувача на час, що може тривати години або
   дні, без утримання worker-процесу (SRS-FUN-11).
4. Сумарне споживання токенів повинно контролюватися на рівні сеансу (SRS-NFR-COST-01).
5. Вузли агентів повинні тестуватися ізольовано з mock-реалізацією LLM.

Ширина графа невелика (4–6 вузлів), проте вимоги 1 і 3 потребують персистентної машини станів.

## Alternatives

### A. LangGraph (StateGraph + PostgresSaver)

- Граф станів з явними вузлами та умовними переходами; `recursion_limit` та лічильник у стані.
- Вбудований checkpointing у PostgreSQL після кожного кроку (`langgraph-checkpoint-postgres`).
- Вбудований `interrupt()` / `Command(resume=...)` для human-in-the-loop без утримання процесу.
- Потокова передача подій вузлів (`astream_events`) для SSE.

### B. Власна оркестрація на Python + Anthropic SDK (tool use)

- Повний контроль над циклом виконання, мінімум залежностей, прямий доступ до нових можливостей
  Claude API без затримки адаптерів.
- Персистентність стану, відновлення, interrupt і потокову передачу подій необхідно
  реалізувати самостійно: таблиця станів, серіалізація, версіонування схеми стану, повторне
  входження в крок.

### C. CrewAI

- Високорівнева модель «ролі та задачі», мінімальний код для лінійних сценаріїв.
- Явний контроль переходів і умовних циклів обмежений; відновлення з довільного кроку після збою
  та призупинення на невизначений час не є основним режимом роботи фреймворку.

## Decision

Обрано **LangGraph** (варіант A).

Критерії порівняння:

| Критерій | LangGraph | Python + SDK | CrewAI |
| --- | --- | --- | --- |
| Checkpoint після кроку в PostgreSQL | Вбудовано | Власна реалізація | Обмежено |
| Interrupt на необмежений час без утримання процесу | Вбудовано | Власна реалізація | Обмежено |
| Явний контроль умовних переходів і лімітів циклу | Так | Так | Частково |
| Потокові події вузлів для SSE | Вбудовано | Власна реалізація | Частково |
| Обсяг інфраструктурного коду, що підлягає тестуванню | Низький | Високий | Низький |
| Прямий доступ до нових можливостей Claude API | Через адаптер | Прямий | Через адаптер |

Варіант B закриває всі вимоги, але переносить на проєкт реалізацію персистентної машини станів,
що є окремою інженерною задачею і не належить до предметної цінності системи. Варіант C не
забезпечує вимог SRS-FUN-11 та SRS-FUN-12 у потрібному обсязі. LangGraph покриває вимоги 1–3
вбудованими механізмами; вимоги 4–5 реалізуються через порти Clean Architecture незалежно від
фреймворку.

## Consequences

### Позитивні

- Відновлення сеансу та human-in-the-loop реалізуються конфігурацією, а не власним кодом.
- Структура графа відповідає діаграмі компонентів та документується тим самим описом вузлів.
- Checkpoint-и зберігаються в наявному PostgreSQL — новий контейнер не потрібен.

### Негативні

- **Залежність від екосистеми LangChain.** API LangGraph і `langchain-anthropic` змінюються
  між мінорними версіями. Заходи: фіксація версій у `uv.lock`, оновлення лише через PR з
  проходженням інтеграційних тестів.
- **Затримка підтримки нових можливостей Claude API** в адаптері `langchain-anthropic`.
  Заходи: порт `LLMPort` дозволяє замінити `ClaudeAdapter` на реалізацію через Anthropic SDK
  без змін у вузлах графа.
- **Vendor lock-in на формат стану.** Таблиці checkpoint-ів мають схему LangGraph; міграція на
  інший оркестратор потребує перетворення збережених сеансів. Заходи: доменні дані (план, задачі)
  зберігаються в окремих таблицях, checkpoint-и вважаються тимчасовими.
- **Зростання обсягу даних checkpoint-ів**: кожен крок зберігає повний стан. Заходи: видалення
  checkpoint-ів завершених сеансів через 7 діб.
- **Складність налагодження**: виконання розподілено між фреймворком і кодом вузлів. Заходи:
  трасування кожного вузла через OpenTelemetry та Langfuse (SRS-NFR-OBS-01).
- **Додаткова залежність у CI/CD**: інтеграційні тести checkpointing потребують PostgreSQL у
  testcontainers, що збільшує тривалість конвеєра.
